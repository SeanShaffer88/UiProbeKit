# UiProbeKit — agent notes

- **The vtable slots in platform.rs are ABI, verified — never edit them from memory.** Every IID, pattern id and slot was checked against the `windows` crate 0.62.2 generated bindings (`src/Windows/Win32/UI/Accessibility/mod.rs`): IUIAutomation ElementFromHandle 6 / RawViewWalker 16; IUIAutomationTreeWalker GetFirstChildElement 4 / GetNextSiblingElement 6 (Next precedes Previous in the vtable); IUIAutomationElement SetFocus 3, GetCurrentPattern 16, CurrentControlType 21, CurrentName 23, CurrentIsEnabled 28, CurrentAutomationId 29, CurrentClassName 30, CurrentIsOffscreen 38, CurrentBoundingRectangle 43; pattern action methods (Invoke/Toggle/SetValue) are slot 3. IUIAutomationElement's IID is D22108AA-8AC5-49A5-837B-37BBB3D7591E — the D6DD68D1 value that circulates from memory is wrong. If a binding ever needs re-checking, re-derive it from the crate source the same way; do not "fix" a slot because a blog post disagrees.
- **BSTR discipline is load-bearing.** Strings the elements hand out are real BSTRs: read with SysStringLen, free with SysFreeString. The set_value string is allocated with SysAllocString — a bare NUL-terminated wide buffer is NOT a BSTR, and a provider reading its length prefix would read garbage. ole32/oleaut32 are resolved dynamically (LoadLibraryW/GetProcAddress); do not add link dependencies to reach COM or UIAutomationCore.
- **No fake success, anywhere.** Off Windows every probe is ERR_NOT_SUPPORTED; a pattern an element does not support is ERR_NOT_SUPPORTED (including when GetCurrentPattern returns UIA's not-supported placeholder — the QueryInterface failure is mapped, not propagated as a platform error); a path that does not resolve is ERR_NOT_FOUND. Never soften one of these into an empty result or UP_OK so a demo looks nicer.
- **Caps are enforced twice on purpose** — the platform walk stops at the spec's WalkLimits, and `serialize_tree` enforces them again on whatever tree it is handed. `truncated` on the root result is the OR of both. Raising the hard parse bounds (depth 256 / nodes 1 000 000) needs a reason; unbounded walks are the failure mode this kit exists next to.
- **Property reads degrade per field; structure never degrades.** A failed getter yields empty/zero for that field and the walk continues (documented in the header + README). Do not "improve" this into aborting the walk, and do not extend it to the walker calls that define the tree's shape — those propagate.
- **The JSON engine (src/json.rs) is the family design** — duplicate keys in one object are a PARSE ERROR by design; do not "fix" that into last-wins. Spec validation (unknown keys rejected, hwnd must be positive, find needs ≥1 criterion, set_value needs a value) runs before the platform check on every platform: argument errors win over NOT_SUPPORTED.
- **Screenshots are out of scope** — CaptureKit covers captures. Do not half-add a capture export here.
- Gate: WinDevKit tools/gate.sh (fmt + clippy both targets + full tests). Check/clippy do not link — CI's real Windows build is the link gate, and reading a real desktop's tree is a field test, not something CI or a VM can claim.
